# 简历口袋：产品需求与设计讨论稿

> 状态：讨论中，尚不是开发承诺。最后整理：2026-10-29。
>
> 本文用于持续讨论产品方向。标记为“已确认”的内容来自用户；“建议”和具体数值只是待确认方案。当前网站的实际能力与本文规划有区别，请以第 2 节为准。
>
> 对应的页面结构、示例文案和交互草图见 [页面方案讨论稿](page-blueprints.md)。

## 1. 产品定位

### 已确认

- 项目中文名称统一为“简历口袋”；现有 `resume-pocket` 是对应的英文技术标识，仓库、部署与数据资源名称不因中文改名而自动变更。
- 主要服务个人求职者：把已有简历保存在线上，在需要时展示、打印、下载，并向招聘方分享。
- 第一版支持上传 PDF 和 Word 文档，Word 包括 DOCX 与 DOC；均需支持在线查看、打印和下载。
- 产品首页应当是介绍产品的落地页；用户的简历工作区和接收方打开的分享页面应当各有自己的页面。
- 为不同公司或个人创建独立分享链接；有效期可选 1 天、2 天、7 天、自定义或永久有效，默认选中 1 天。
- 接收方打开有效分享页时，默认可以打印和下载简历。
- 同一份简历上传新版后，已有的有效分享链接自动展示该简历的最新版本。
- 第一版分享页提供可自愿填写的公开信息卡及每条链接独立的投递留言；未填写的内容不显示，私人备注保持隐藏。
- 统计数据集中在后台：用户查看自己的数据，管理员查看全站汇总；第一版包含简历数量、分享状态和访问次数。
- 用户可以手动停用自己正在分享的链接，也可以重新启用；访问已停用链接时显示停用信息，5 秒后跳转到产品首页。停用前已经打开的页面也应尽快显示停用提示，再在 5 秒后跳转。
- 视觉方向：简洁专业、克制、清晰、可信。
- 未登录的访客也可以直接上传简历并创建分享，无需先注册；游客可用的功能少于登录用户。具体开放与关闭范围见 [6.3 节](#63-游客模式免登录上传与分享)，首版已按该范围实现上传、预览与删除，分享链接与登录用户一样尚待接入后端。
- 将来希望支持在线制作简历；暂不把它等同于本阶段已经提供的功能。
- 首版之后陆续支持更多文档与图片格式（例如 JPG、PNG 图片简历），首页“规划中”只作方向说明，不承诺时间。
- 项目源码放在 GitHub，网站部署在 Cloudflare。

### 一句话价值主张（建议）

**保存一份简历，为每一次机会安心分享。**

求职者不需要随身携带纸质简历，也能向不同招聘对象提供可控、易打开的简历链接。招聘方不需要注册，就能在链接有效时查看简历。

### 本阶段的边界（建议）

以 PDF、DOCX 和 DOC 为首版文件格式，完成“了解产品 → 注册登录 → 保存简历 → 为招聘对象创建链接 → 对方查看 → 管理或停用链接”的闭环。同时提供不需要注册的游客路径：“了解产品 → 上传简历 → 创建有期限的链接 → 对方查看 → 停用或等待自动过期”，作为体验入口和一次性投递的轻量方式。首页、工作区、游客空间和分享页使用统一设计体系，但服务不同的任务。

## 2. 当前产品与差距

以下根据当前项目文件和已部署页面核对，不代表下一版的目标全部已经实现。

| 方面 | 当前情况 | 下一步需要解决的问题 |
| --- | --- | --- |
| 产品首页 | 根地址直接展示简短标语、登录和简历工作区 | 现有介绍不足以说明完整价值、使用步骤、示例和常见问题 |
| 用户工作区 | 支持邮箱密码注册登录、PDF 上传、预览、打印、下载和删除 | 缺少分享管理、统计后台、明确的账户恢复及更完整的空间管理 |
| 接收方页面 | 尚无分享功能 | 需要独立、统一的简历展示页及失效状态 |
| 文件范围 | 注册用户支持 PDF、DOCX、DOC，单个文件最大 10 MB；游客仅 PDF | Word 在 Cloudflare Containers 中用 LibreOffice 转为 PDF 预览与打印，原件私有保存、默认下载原件；转换效果仍需用真实中文简历样例验证；在线制作未实现，首页只标为规划中 |
| 账户 | 支持密码登录；尚无邮箱验证或密码找回 | 面向公众使用前需要完善账户可恢复性和滥用防护 |
| 游客使用 | 不支持；上传和查看简历都必须先登录 | 需要游客空间、管理凭证、匿名滥用防护、数据自动清理及转为正式账户的方式 |
| 工程与运营 | Cloudflare Workers、D1 和 R2；GitHub 有自动检查 | 目前部署并非由 GitHub 推送自动完成；配额、备份恢复和发布治理仍需完善 |

现有首页视觉有基础，但把产品介绍、登录和工作区混在同一屏；新用户看不清完整使用方式，招聘方也没有一个专门的查看入口。改版的重点是重新建立页面职责和完整流程，而不是只换一套颜色。

## 3. 用户与核心场景

| 角色 | 想完成的事 | 成功结果 |
| --- | --- | --- |
| 访客 | 判断产品是否适合自己 | 不注册也能理解用途、操作步骤和隐私边界 |
| 游客（未登录的求职者） | 临时投递一份简历，不想先注册 | 在当前浏览器上传简历，创建有期限的链接并发出；需要时停用链接，或注册后长期保留 |
| 求职者 | 保存、查看和管理自己的简历 | 在电脑或手机上找到自己的文件并可打印、下载或删除 |
| 求职者 | 向不同招聘对象投递 | 为每个对象创建独立链接，选择有效期或永久有效，之后能查看状态或停用 |
| 求职者 | 查看分享情况并管理访问 | 在后台查看自己的简历数量、链接状态和访问次数；需要时停用或重新启用链接 |
| 招聘方 / 接收人 | 快速查看收到的简历 | 无需创建账号，打开有效链接即可阅读，默认可打印和下载 |
| 管理员 | 了解网站整体使用情况 | 在后台查看全站汇总数据，不默认查看他人的简历内容或私人备注 |

### 核心路径

1. 访客进入首页，了解产品和简历分享方式，点击“开始使用”。
2. 求职者注册或登录，进入自己的工作区，上传一份 PDF、DOCX 或 DOC 简历。
3. 用户预览确认，选择“分享”，填写仅自己可见的公司或联系人备注并选择有效期。
4. 系统创建该对象的独立链接；用户自行复制并发送。
5. 接收人打开链接，在标准分享页查看简历；链接到期或被停用后无法再次获取文件。
6. 用户在工作区查看自己创建的链接及状态，必要时停用或重新启用。
7. 用户为同一份简历上传新版后，尚有效的链接在下一次打开时展示新版；分享期限和停用状态保持不变。
8. 用户在统计后台查看自己的数据，可将正在分享的链接停用或重新启用。接收方打开已停用链接时看到提示，并在 5 秒后回到产品首页。

### 游客路径

1. 访客在首页选择“无需注册，直接上传”，进入 `/try` 上传一份简历（人机验证上线前补上）。
2. 系统创建只属于当前浏览器的游客空间，并显示“管理链接”，提示用户自行保存，用于在其他设备或清除浏览器数据后继续管理。
3. 游客预览确认后创建分享，选择 1 天、2 天或 7 天有效期，可填写对象备注、投递留言和公开信息卡。
4. 接收人打开链接看到的分享页与登录用户的分享页相同，不显示“游客”标记。
5. 游客可随时停用链接或删除简历；空间到达保留期限后自动删除。
6. 游客注册或登录后，可把游客空间中的简历和链接并入账户，链接地址保持不变。

### 如何判断是否有用（建议）

- 观察新用户从首页进入工作区、成功上传第一份简历、创建第一条分享的完成情况，找出流失环节。
- 观察有效链接能否在常见手机和桌面设备上顺利打开，以及因过期、加载错误或权限问题而失败的比例。
- 统计与诊断尽量采用汇总数据，不收集简历内容、完整分享链接或招聘对象备注；具体指标目标和隐私方案在上线前确定。

## 4. 页面与导航建议

| 页面 | 建议地址 | 谁能访问 | 主要任务 |
| --- | --- | --- | --- |
| 产品首页 | `/` | 所有人 | 了解产品，进入注册/登录，查看不含真实个人信息的示例 |
| 注册与登录 | `/login`、`/signup` | 所有人 | 创建账号、登录及恢复账号 |
| 我的简历 | `/app` 或 `/app/resumes` | 已登录用户 | 上传、预览、管理文件和创建分享 |
| 游客空间 | `/try`，管理链接为 `/try#k=<管理凭证>`（凭证在 `#` 之后，不随请求发送） | 未登录访客；凭当前浏览器或管理链接 | 上传一份简历、创建并管理少量有期限的链接，提示保留期限与注册方式 |
| 分享管理 | `/app/shares`，或从对应简历进入 | 已登录用户 | 查看、复制、停用或重新启用自己创建的链接 |
| 数据统计 | `/app/analytics` | 已登录用户；管理员另有全站汇总 | 集中查看对应权限范围内的简历数量、分享状态和访问次数 |
| 简历分享页 | `/s/<分享标识>` | 持有效链接者 | 查看对应简历和可用操作 |
| 隐私与服务说明 | `/privacy`、`/terms` | 所有人 | 说明数据处理、删除、使用边界与联系方式 |

地址是信息架构建议，最终路由可调整。未登录访问工作区时应引导登录；登录完成后回到用户原本想访问的工作区。首页对已登录用户的主要按钮应改为“进入工作区”。

## 5. 首页：内容与功能

### 内容结构（建议）

| 顺序 | 内容 | 用户应得到的答案 |
| --- | --- | --- |
| 1 | 导航：产品标识、功能介绍、使用方式、常见问题、登录和开始使用 | 这是什么，我如何开始 |
| 2 | 首屏：明确标题、简短说明、主要按钮（“开始使用”与“无需注册，直接上传”），以及真实可理解的产品界面示例 | 我可以保存什么，能解决什么问题 |
| 3 | 三步说明：上传简历、创建分享、对方打开 | 从开始到分享需要做什么 |
| 4 | 核心能力：保存与预览、打印下载、分对象分享与有效期 | 产品目前真正能做什么 |
| 5 | 示例分享页：使用虚构内容展示接收方体验 | 招聘方打开后看到什么 |
| 6 | 隐私与控制说明：私有空间、链接有效期、手动停用及转发边界 | 我的简历会给谁看到，如何停止分享 |
| 7 | 常见问题：支持格式、是否要注册、链接到期、对方能否下载、密码找回 | 使用前的常见疑问 |
| 8 | 页脚：隐私与服务说明、联系途径、项目相关信息 | 如何了解规则或寻求帮助 |

### 首页功能取舍

- **建议首版包含**：开始使用、登录、免注册上传入口、跳转至首页内容区、查看虚构示例、隐私/服务说明、常见问题。首页应说明游客与注册用户的差别，不把游客模式描述成与账户完全相同。
- **可以在完成基础闭环后考虑**：手机扫码打开分享页、用户反馈入口、无障碍说明、语言切换。
- **暂不放入首版核心流程**：公开简历搜索、招聘职位市场、企业管理后台、AI 润色、套餐价格表和用户评价墙。这些功能需要单独的需求与真实内容支撑。
- 在线制作可以标记为规划中，但不得展示成已经可以使用的按钮或承诺确定发布日期。
- 不使用虚构的用户数量、企业客户、评价、收费承诺或安全认证；所有示例简历必须使用虚构数据。

## 6. 求职者工作区

### 6.1 账户与个人空间

| 编号 | 需求 | 优先级 | 说明 |
| --- | --- | --- | --- |
| A-01 | 注册、登录、退出 | P0 | 保持每位用户的简历与分享记录隔离 |
| A-02 | 邮箱验证和密码找回 | P0，建议作为开放注册的发布条件 | 给用户恢复访问的途径；验证与发送邮件的具体方案待确定 |
| A-03 | 账户删除和数据清理 | P1 | 明确删除范围、确认操作及处理时间 |
| A-04 | 简历数量、存储空间及防滥用限制 | P0，具体额度待确定 | 避免无限制上传和无法预期的费用；达到限制时明确提示 |

P0 表示本阶段上线所需；P1 为紧随其后的增强；P2 为后续方向。优先级是建议，尚待确认。

### 6.2 简历文件管理

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| R-01 | 上传 PDF、DOCX 和 DOC | P0 | 三种格式均可上传并查看；PDF 现行上限为 10 MB，Word 和最终上限待验证；错误格式、损坏文件和超限文件有清晰提示 |
| R-02 | 列表与选择 | P0 | 展示文件名、大小、上传时间；最近上传在前；空状态指导上传 |
| R-03 | 预览、打印、下载 | P0 | 支持多页；下载为原文件；打印前预览完整；手机不支持直接打印时提供下载方式 |
| R-04 | 删除文件 | P0 | 删除前明确提示相关分享将失效，确认后使关联分享失效并删除文件 |
| R-05 | 更新已有简历 | P0 | 为同一份简历上传新版成功后，该简历的有效分享自动显示新版；独立上传其他简历不应改变它的分享 |
| R-06 | Word 在线预览与打印 | P0 | DOCX 和 DOC 均需生成可阅读、可打印的预览；转换中、失败和不支持的文件有明确提示；预览效果和资源成本须在上线前验证 |
| R-07 | 历史版本管理 | P1 | 是否保留历史、回退或查看版本记录待讨论；不得影响首版自动显示最新版本的要求 |

对加密、损坏或设备不兼容的文件，预览失败时应解释原因，并在允许时提供原文件下载。用户上传的 PDF 本身保留原排版；分享页的“模板”是外围展示框架，不重新排版或改写简历内容。

**Word 处理方案（已实现，效果待样例验证）**：私有保存原始 DOCX 或 DOC，将其转换为 PDF 供在线预览和打印，默认下载原始 Word 文件；也可进一步评估提供 PDF 下载。转换可能改变字体、分页或图表，应在分享前让求职者检查预览并确认；转换失败或尚未完成时不发布新版，已有分享继续显示上一份可用版本。转换服务、字体覆盖、文件大小与等待时间需通过中文、多页、复杂排版和旧版 DOC 样例验证，不能假定格式完全一致。转换过程中要保护私人文件，禁用宏及外部资源访问；若拟使用外部服务，需先明确其数据处理与保留方式，并向用户说明及取得必要同意。当前实现：转换在本站 Cloudflare 账户内的 Containers 实例中用 LibreOffice 完成，文件不交给第三方；容器禁止访问外网，宏执行被禁用，转换使用临时目录且完成即删除；常见中文字体（宋体、微软雅黑、黑体、楷体、仿宋、等线等）映射到思源字体，个别字形和字距会与 Word 不同。转换失败时整次上传作废，不保存任何文件。费用来自 Workers Paid 套餐内的容器用量，超出部分按用量计费。

### 6.3 游客模式：免登录上传与分享

**已确认**：未登录用户可以上传并分享简历，功能少于登录用户，属于首版功能。以下开放范围由产品判断确定，数值可在上线后按成本与滥用情况调整。

取舍原则：凡是关系到接收方体验和求职者撤回能力的功能都向游客开放；需要长期保管、跨设备身份或较高成本的功能留给注册用户。游客没有可恢复的账户，链接越长期，越可能变成无人管理的公开文件。

| 能力 | 游客 | 登录用户 | 判断理由 |
| --- | --- | --- | --- |
| 上传简历 | 开放：同时保存 1 份；首版仅 PDF，最大 10 MB | 多份，按账户配额 | 控制匿名存储成本与滥用；Word 转换成本较高，上线后再评估是否向游客开放 |
| 预览、打印、下载自己的简历 | 开放 | 开放 | 上传后必须能确认内容 |
| 更新为新版 | 关闭：删除后重新上传，链接需重新创建 | 开放 | 替换会让 14 天保留期的起点含糊，并让匿名链接背后的内容可被随时换掉；游客链接最长 7 天，重发成本低 |
| 删除简历 | 开放：立即删除，并使全部链接失效 | 开放 | 求职者必须能随时撤回 |
| 创建分享链接 | 开放：同时最多 3 条有效链接 | 按账户配额 | 满足一次投递几家公司的需要，又限制批量传播 |
| 有效期 | 1 天、2 天、7 天，默认 1 天 | 另有自定义与永久有效 | 游客空间无法长期保管，不开放永久和超过 7 天的期限 |
| 对象备注、投递留言、公开信息卡 | 开放，规则同登录用户 | 开放 | 属于分享页的核心体验 |
| 手动停用与重新启用 | 开放；重新启用不超出原有效期 | 开放 | 撤回能力是隐私底线 |
| 访问统计 | 仅在链接列表显示每条链接的访问次数 | 完整的数据统计后台 | 保留最有用的反馈，不为游客提供总览后台 |
| 跨设备管理 | 仅能凭管理链接 | 登录即可 | 游客没有账户身份 |
| 发送到聊天应用 | 开放：Telegram、WhatsApp、邮件及系统分享 | 开放 | 见 S-13 |
| 多份简历、账户设置、数据总览 | 关闭 | 开放 | 需要账户身份或长期保存 |
| 转为正式账户 | 注册或登录后可并入账户（P1） | — | 并入后解除游客限制，已有链接地址、有效期和状态不变 |

**身份与管理凭证**：首次上传时创建随机的游客空间凭证，保存在当前浏览器的 HttpOnly Cookie 中（14 天）；同一浏览器内可随时再次查看管理链接 `/try#k=<凭证>`。服务端只用凭证摘要定位文件，不保存凭证原文。在其他浏览器打开管理链接即恢复管理；也可在当前浏览器退出游客空间（不删除简历）。界面必须清楚区分“分享链接”（发给招聘方）和“管理链接”（只给自己，相当于密码）；管理链接不出现在分享页、统计事件或日志中。Cookie 和管理链接都丢失后，游客无法再管理这份简历，只能等待自动删除；这一点应在上传前说明。

**数据保留**：游客简历在上传 14 天后自动删除，分享链接随之失效；链接有效期不能晚于删除时间。到期后服务端立即拒绝访问，存储中的文件由生命周期规则清理。游客页面显示删除日期。游客没有邮箱，系统不发送到期提醒。

**防滥用**：已按网络来源限制游客上传与管理链接恢复的频率（每分钟 5 次）。上线前还需：游客上传和创建链接前进行人机验证（例如 Cloudflare Turnstile）；按网络来源和全站总量限制游客上传与创建链接的频率，并为游客存储设总量上限，超出时暂停游客上传并引导注册；分享页提供不泄露分享者信息的举报入口；管理员可以紧急停用游客内容。服务说明应写明游客同样需遵守上传规则。

**游客限制提示**：达到数量、有效期或保留期限的限制时，说明原因及注册后可获得的能力，不使用倒计时、弹窗轰炸等施压方式，也不因游客未注册而降低分享页对接收方的体验。

## 7. 分享：对象、有效期与访问边界

### 7.1 已确认的分享方式

每个招聘公司或联系人使用独立链接，可以分别选择 1 天、2 天、7 天、自定义有效期或永久有效，默认选中 1 天。永久有效表示不设自动到期时间，用户仍可手动停用或重新启用链接；删除关联简历也会使链接失效。公司或联系人名称是求职者管理链接的**备注**，便于区分投递对象；备注默认只在求职者自己的工作区可见。有效分享页默认允许接收方打印和下载。同一份简历更新后，已有有效链接展示它的最新版本。

**重要边界：专属链接并不核验接收人身份。**任何拿到有效链接的人都可能打开它，包括被转发的人员。如将来需要限制为某个邮箱或企业人员，必须另行增加身份验证或其他访问控制。

### 7.2 创建与管理（建议）

| 编号 | 需求 | 优先级 | 验收要点 |
| --- | --- | --- | --- |
| S-01 | 按简历、对象创建独立链接 | P0 | 同一份简历可有多个独立链接；不同对象的标识不可相同 |
| S-02 | 选择有效期 | P0 | 创建时可选 1 天、2 天、7 天、自定义或永久有效；默认选中 1 天 |
| S-03 | 复制和再次查看链接 | P0 | 创建后可复制；管理页能重新复制仍有效的链接，并清楚标明其对象以及到期时间或永久有效状态 |
| S-04 | 查看链接状态 | P0 | 所有者可区分生效、已过期、已停用及关联文件已删除等状态 |
| S-05 | 手动停用与重新启用 | P0 | 用户可停用和重新启用自己的链接；停用后随即停止新的页面、预览和下载请求，已打开的页面尽快显示停用提示；其他链接不受影响 |
| S-06 | 文件删除联动 | P0 | 删除简历时明确告知关联链接数量，并使这些链接全部失效 |
| S-07 | 接收方打印和下载 | P0 | 有效分享页默认允许打印和下载；建议默认下载上传的原始 PDF、DOCX 或 DOC 文件 |
| S-08 | 访问密码或邮箱身份验证 | P2 | 属于额外保护，不是首版已确认需求；需单独确定体验及成本 |
| S-09 | 访问统计 | P0 | 用户在后台查看自己分享的访问次数；管理员查看全站汇总；口径和隐私边界见第 7.4 节 |
| S-10 | 打印与下载控制开关 | P1 | 后续可评估是否允许求职者关闭入口；关闭入口不能阻止截图或其他复制方式 |
| S-11 | 公开信息卡 | P0 | 求职者自愿填写，并为每条分享选择展示姓名、目标岗位、所在地或联系方式；未填写或未公开的字段不显示，不能自动使用账户或 PDF 中的资料 |
| S-12 | 每条链接的投递留言 | P0 | 求职者可选填写面向接收方的说明；各链接内容独立，不得使用或暴露私人备注 |
| S-13 | 发送到聊天应用 | P0 | 链接可一键发送到 Telegram、WhatsApp、邮件或系统分享面板，附带投递留言；不提供发布到 X、Facebook 等公开平台的按钮，原因见 D-14 |

**建议规则**：有期限链接的到期时间由服务端判断并存储为统一时间，界面以用户本地时间清楚显示；到达约定时刻即视为过期。永久有效链接不设置到期时间，但仍可被手动停用或因文件删除而失效。单纯到期的链接是否允许延长，留待确认。

**停用与重新启用**：手动停用不删除简历或分享记录；用户主动重新启用后，仍在有效期内或永久有效的原链接恢复访问，其他链接不受影响。重新启用前应提示：此前持有或转发过原链接的人会重新获得访问能力。建议已过期的停用链接在重新启用前先选择新的有效期，不能绕过过期规则；具体交互仍待确定。

**已确认的版本行为及建议交互**：分享链接关联一份简历，而非固定在某次上传的文件上。同一份简历更新成功后，已有有效链接在下一次打开时显示最新版本；链接地址、有效期和打印/下载权限不因此改变，已过期或已停用的链接也不会因为更新简历而自动重新生效。建议将“上传新简历”和“更新这份简历”设计成不同操作：前者创建另一份简历，后者明确替换当前简历的展示版本，并提示会影响现有分享。新版上传失败时继续显示原版本。正在查看旧版的接收方可能需要刷新才能看到新版；已展示内容不能被强制收回。

**不可撤回的边界**：链接过期或停用后，系统可以拒绝后续访问，但不能收回接收方已经下载、打印、截图或另存的内容；打开页面时应避免承诺“绝对防复制”。

### 7.3 状态与异常

- 有效链接：展示简历和允许的操作。
- 链接被手动停用：向接收人显示“此分享已停用”，不泄露简历或所有者信息；页面显示 5 秒后自动跳转到产品首页 `/`，并提供可立即点击的“返回首页”。停用后又到期的链接仍按已停用展示；删除文件后的展示按文件已删除处理。
- 停用前已打开的分享页：页面检测到停用后尽快移除简历、公开信息和投递留言，禁用打印与下载，显示同样的停用提示，并从提示出现开始计时 5 秒后返回首页。检测前或离线期间无法保证立即收到状态变化，已经下载、打印或截图的内容不能被收回。
- 链接不存在、已过期或文件已删除：向接收人显示“链接不存在或已失效”，不泄露简历名称或所有者信息。这些状态是否也需要 5 秒后跳转，待确认。
- 服务暂时不可用或网络中断：提示稍后重试，不把暂时故障描述为链接已过期或已停用；连接恢复后重新检查状态。
- 预览加载失败：提示查看失败；如果该链接允许下载，提供下载原文件的途径。
- 时间到期或停用发生在接收方已打开页面之后：已有内容无法强制抹除，但后续文件请求必须再次检查权限。
- 创建或删除时网络中断：提示操作是否完成；重试不应意外产生重复链接。停用链接与删除文件跨不同存储步骤时，部分失败不能错误地提示全部成功，应可安全重试。

### 7.4 统计后台

#### 已确认范围

- **用户侧**：登录用户在后台查看自己的简历数量、分享链接状态和访问次数，不得查看其他用户的个人统计或私人备注。
- **管理员侧**：管理员可查看全站汇总的上述数据；管理员权限需要独立管理，普通用户不能自行取得。
- **游客侧（建议）**：游客只在自己的链接列表中看到每条链接的访问次数，不提供统计后台；管理员汇总中区分游客与注册用户的数据。
- **第一版指标**：简历数量、分享状态、访问次数。下载、打印次数和访问者身份不在本轮确认范围内。

#### 展示建议

| 页面或位置 | 建议内容 | 边界 |
| --- | --- | --- |
| 用户数据总览 | 自己的简历总数、分享总数及各状态数量、分享访问次数 | 只包含当前用户的数据；展示最后更新时间 |
| 用户分享列表 | 简历、自己填写的对象备注、状态、有效期和每条链接的访问次数 | 可从列表停用或重新启用自己的链接；不显示访问者身份 |
| 管理员汇总 | 全站简历数量、分享总数及各状态数量、网站与分享访问的汇总次数，按游客与注册用户分别统计 | 仅向管理员开放；汇总不默认包含简历内容、个人联系方式、完整分享链接或私人备注；游客没有账户，不出现在用户列表中 |

**统计口径建议**：区分产品首页访问和有效分享页访问；用户侧仅展示自己的有效分享页访问次数。一次有效页面访问按一次页面展示计算，PDF 分页、预览文件请求、下载请求或定期状态检查不应被当作新的页面访问。刷新或链接预览工具可能产生重复访问，数据可能有延迟且不能证明是独立访客或某位招聘方已阅读。管理员统计的首页与分享页访问不应混为同一种事件；最终口径可继续讨论。

**隐私与安全**：统计事件不记录简历内容、完整分享链接、账户密码或私人备注；分享管理列表可以从分享记录中向所有者显示其本人填写的备注。不能仅凭匿名链接声称识别访问者身份。管理员权限由服务端验证，统计和管理接口不得允许通过修改用户标识访问他人数据。无数据时展示明确空状态而不是虚构数字。

## 8. 标准简历分享页

### 推荐方向

分享页是面向招聘方的完整阅读页面：既要让人方便阅读简历，也要说明内容从何而来、在不同设备上如何操作，并在出现问题时给出明确反馈。模板负责外围展示与交互；PDF 保持原有排版，Word 预览需要转换且效果应由求职者确认。页面不应挤占简历内容或用营销内容打断阅读。

### 分享页内容

| 区域或能力 | 建议内容 | 理由与边界 |
| --- | --- | --- |
| 页头 | 轻量产品标识、通用标题“简历预览”及简短分享说明 | 让接收方知道当前页面用途；不默认展示账户邮箱或私人投递备注 |
| 可选公开信息卡（首版已确认） | 求职者主动选择展示姓名、目标岗位、所在地或联系方式；未填写或未选择展示的字段不出现 | 帮助招聘方快速了解候选人；联系方式只在求职者明确同意后展示，不从 PDF 或账号自动提取 |
| 可选投递说明（首版已确认） | 每条分享可自愿填写一句针对该对象的公开说明，例如“应聘产品经理岗位，感谢查阅” | 把向招聘方展示的内容与仅自己可见的公司/联系人备注分开；不同链接的说明互不影响 |
| 简历阅读 | 按页展示 PDF 或 Word 转换后的预览，提供页码、适应屏幕宽度和缩放 | 多页简历便于定位；支持桌面和手机；不自动改写或提取个人信息 |
| 文件操作 | 默认打印和下载；建议下载原始 PDF 或 Word 文件 | 为招聘方提供直接使用的方式；手机无法直接打印时说明可先下载 |
| 分享状态 | 加载中、有效、失效、预览失败、服务故障等状态 | 出错时提供可执行的下一步，不把网络故障误报为链接失效 |
| 数据边界 | 默认不展示用户的邮箱、私人备注或从 PDF 推断出的姓名与岗位 | 居于页面外的个人信息应由求职者明确选择提供 |
| 页面底部 | 简短隐私说明、产品首页入口 | 保持辅助信息克制，不放妨碍阅读的注册弹窗或广告 |

上述公开信息卡和投递说明**已确认纳入首版，填写自愿**：用户不填写时，分享页仍应完整可用。创建分享时应让用户清楚看到该链接将公开哪些字段和留言；公开信息和联系方式对任何持有有效链接的人可见，不应被描述为只能由指定公司查看。公开内容与 PDF 可能不同步，编辑界面应允许求职者检查和修改。信息卡内容修改后是否同步到已创建的链接，仍待确定。

### 可选增强建议，待讨论

- **阅读辅助**：在合适设备上提供全屏阅读和可访问的文字选择；扫描型 PDF 可能没有可选择文字，应保留原文件下载方式。
- **更新时间**：允许求职者决定是否对接收方显示简历最近更新时间；新版自动生效，但是否展示时间待确认。
- **线下使用**：在求职者工作区提供分享二维码，便于现场展示；不在招聘方页面主动鼓励转发私人链接。

具体页面结构、候选文案、桌面/手机示意和状态处理见[页面方案讨论稿](page-blueprints.md)。以上增强是建议，并非已确认的首版承诺。

## 9. 设计体系与质量标准

### 设计方向（已确认）

简洁专业、克制、清晰、可信。使用明确的层级、充足留白和易读的中文字体；视觉重点应放在产品价值和简历内容，而不是装饰。首页可以有品牌表达，工作区注重效率，分享页优先阅读。

### 设计交付（建议）

- 在实现前形成桌面和手机两套关键页面方案：产品首页、空/有文件的工作区、创建分享、有效/失效分享页。
- 定义可复用的颜色、文字、间距、按钮、表单、提示、对话框、文件列表和预览组件，并覆盖加载、空、错误和禁用状态。
- 视觉内容使用真实可实现的功能和虚构简历示例；不要用虚构数据制造信任感。
- 以 WCAG 2.2 AA 为设计目标，重点检查对比度、键盘操作、焦点、表单标签与错误提示；移动端和桌面端均可完成核心任务。
- 首页可被搜索引擎正常发现；私有工作区和分享内容默认不作为公开索引内容。`noindex` 只是搜索提示，不能代替访问控制。
- 建议以真实用户数据的第 75 百分位为长期性能目标：LCP ≤ 2.5 秒、INP ≤ 200 毫秒、CLS ≤ 0.1；先建立测量与基线，再评估是否达标。

## 10. 更成熟的实现方案比较

| 方案 | 适合点 | 代价和限制 | 判断 |
| --- | --- | --- | --- |
| A. 升级现有项目 | 可保留已上线账户和 PDF 空间，优先完成首页、分享和稳定性 | 需要补齐产品设计、账户恢复、分享能力、配额和发布治理；当前使用的 Vinext 为测试版，需要评估长期维护风险 | **建议先做的候选方案**，但先做技术验证，不将现状直接视为工业级 |
| B. 以 Reactive Resume 为主体 | 已有较完整的简历编辑、模板、预览与导出体验，开源许可允许按条件复用 | 官方 Cloudflare 方案需要 Workers Paid、独立 PostgreSQL/Hyperdrive 等资源；与现有 D1 数据结构并非直接兼容；定向有效期分享及现有数据迁移仍需验证 | 若在线编辑很快成为核心，可以做小范围验证，再决定是否迁移 |
| C. 保留分享产品，后续独立接入编辑器 | 先解决投递闭环，同时保留选择成熟编辑能力的空间 | 账户、数据格式、导出、权限和体验需要统一；不能预设两个系统天然兼容 | 适合编辑功能成为明确需求后再评估 |

Reactive Resume 的公开仓库和部署文档表明，它支持 Cloudflare Workers，但目前的 Cloudflare 方案仍依赖 PostgreSQL，经 Hyperdrive 连接，并不是把现有 D1 项目直接替换即可。其仓库当前标注 MIT 许可；OpenResume 当前标注 AGPL-3.0，两者不能视为同一种复用条件。OpenResume 可作为简历制作和 PDF 导入体验的补充参考。引入任何代码之前，应针对选定版本核对许可、依赖、费用、隐私边界、升级方式以及中文和移动端体验。

### 建议的工程边界

- 产品展示、已登录工作区与匿名分享访问保持清晰边界；共享设计组件，不共享用户权限。
- 文件存放在私有存储；分享链接使用不可猜测的独立标识。服务端保存标识摘要用于校验，并加密保管可恢复的标识，使所有者登录后仍能重新复制链接；关联简历、所有者、创建时间、到期时间和状态分开记录，日志不记录完整链接。加密密钥的保管、轮换和丢失后的重新分享方式必须事先明确。
- 每次请求分享页、预览、下载或打印所需文件时都检查对应链接是否有效；不得依靠仅在浏览器隐藏按钮来保护文件。
- 公开信息卡和投递说明仅在对应分享有效时提供；输入按纯文本处理并限制长度，不自动填入私有备注或账户资料。
- 分享内容响应避免被共享缓存；设置适当的 `no-store`、`noindex` 和 `no-referrer` 等保护，限制第三方脚本和链接预览泄露。它们是辅助措施，不代替权限验证。
- 停用页跳转到不携带分享标识的产品首页；页面内容、跳转地址、统计事件和日志不包含旧链接标识、简历或公开信息卡。为跳转提供无需脚本时的回退和手动返回入口。
- 已打开的分享页需要主动感知链接状态，例如通过定期检查或服务端通知；页面恢复到前台及网络恢复时也应检查。正常联网且页面处于前台时的检测时间目标需在方案中明确并验证，不能把网络故障当作已停用。
- 紧急停用、额度限制、上传验证、日志脱敏、错误监控、备份与恢复演练、预发布环境、可回滚部署均应纳入上线方案。
- 数据模型应区分“简历”和其上传版本，分享关联简历并解析到当前版本；发布新版应在上传及所需转换完成、预览确认后切换，避免接收方读取到不完整文件。同一已打开页面的预览、打印和下载建议对应同一版本，重新打开或刷新后展示新版；每次后续文件请求仍须验证分享是否有效。将来还应允许“在线编辑的结构化简历”和上传的 PDF、Word 原件并存。
- 游客空间与注册账户使用同一套简历、版本和分享模型，以“所有者类型”区分；权限检查同样在服务端完成。管理凭证与分享标识分开生成和保存；游客数据的自动删除需要定时任务及失败重试，并保证删除后分享和文件请求立即失效。
- 迁移时保留现有真实账户与文件，先验证备份、迁移和回滚；生产数据库变更应依照工作区安全要求单独处理。

## 11. 阶段与验收

### 阶段一：产品展示与可控分享（建议）

在明确方案和视觉方向后，交付首页、账户恢复、私有工作区、统计后台、按对象创建可设置期限或永久有效的分享、分享页、停用与重新启用，以及必要的运营保护。首版支持 PDF、DOCX 和 DOC 的上传、预览、打印和下载；当前网站已支持注册用户上传 Word，游客仍仅支持 PDF。

最低验收场景：

1. 新访客打开首页，可不登录了解产品、打开虚构示例并进入注册；首页不出现用户私人数据。
2. 求职者登录后上传两页 PDF，完成预览、下载、打印入口和退出；另一个账号不能读取或删除该文件。
3. 同一简历分别创建给公司 A 与公司 B 的链接；可选 1 天、2 天、7 天、自定义或永久有效，默认 1 天；各自的有效期和停用状态互不影响，备注仅所有者可见。
4. 未登录接收人打开有效链接可查看两页简历，默认可打印和下载；文件读取也受同一链接权限保护。
5. 有期限的链接到期或任意链接被停用后，页面及直接文件/下载请求都不能再获得文件；永久链接不会因时间流逝自动过期；删除原文件使所有相关链接失效。
6. 受支持的手机和桌面浏览器可完成核心流程；键盘可操作；错误、空和加载状态均有明确反馈。
7. 更新同一份简历后，原有有效链接重新打开时显示新版；新上传另一份简历不会改变旧链接；更新失败、链接过期或停用均不会使链接错误恢复。
8. 未公开的信息卡字段和私人备注不能出现在分享页；不同链接的公开留言不能串用；无效链接不泄露这些内容；未填写可选信息时分享页仍可正常使用。
9. 用户停用链接后，新访问者打开原链接看到停用提示，5 秒后回到产品首页，也可立即手动返回；直接预览和下载请求不能获取文件，停用页不泄露简历或公开资料。停用前已打开且正常联网的页面应尽快移除简历内容、显示同样提示，并在提示出现 5 秒后返回首页。
10. 用户重新启用未过期链接后，原链接重新可用；其他链接状态不受影响。非所有者不能停用或重新启用该链接；过期链接不能绕过有效期直接访问。
11. 普通用户只能查看自己的简历数量、分享状态和访问次数；管理员可查看全站汇总；分页文件请求不造成重复页面访问计数。
12. 验证账号找回、上传限制、备份恢复、发布与回滚；不能以“看起来可以运行”代替这些检查。
13. 分别使用虚构的 PDF、DOCX 和 DOC 简历，验证上传、多页预览、打印、原件下载和分享；覆盖中文、字体、图片、表格和分页，并由求职者确认 Word 转换后的效果。
14. 验证损坏、加密、超限或转换失败的 Word 文件有清晰反馈；新版转换未完成或失败时，原分享仍可显示上一份可用版本，完成且确认后才显示新版。
15. 未登录访客可通过首页完成上传、预览和创建 1 天、2 天或 7 天的链接，接收方体验与登录用户的分享页一致；游客无法创建永久或超过 7 天的链接，超出 1 份简历或 3 条有效链接时有明确提示。
16. 游客在其他浏览器中凭管理链接可以停用、重新启用链接或删除简历；没有 Cookie 或管理链接的人无法管理；分享链接不能用作管理链接。
17. 游客简历上传 14 天后，文件、分享页及直接文件请求均不可再访问；游客注册后并入账户，原链接地址、有效期和状态保持不变。

### 阶段二：分享体验增强（建议）

依据实际使用情况评估分享密码、二维码、权限开关、版本管理或更详细的统计指标；先验证是否真有需求，再确定优先级。

### 阶段三：在线简历制作（已提出，范围待定）

支持结构化内容编辑、模板选择、预览和 PDF 导出是候选方向。是否支持从现有 PDF 导入、多个语言版本、AI 辅助、求职跟踪等，另行讨论。编辑器可复用成熟项目，也可独立实现；以验证结果决定，不在本阶段承诺方案。

## 13. 建议优先完善的事项

以下是基于当前需求提出的建议，不改变前文已确认的决定。

| --- | --- | --- |

| 高 | 已打开页面多久感知链接停用 | 建议先以正常联网、前台页面在约 10 秒内检测到停用为设计目标，显示提示后再等 5 秒跳转；检测频率、成本和网络异常需验证后确定。 |

| 高 | 存储、备份和删除 | 确定每人文件数量及容量限制、备份恢复方式和删除后数据如何处理；现有账户和文件迁移前先验证恢复方案。 |
